# FAB DeWEB Browser

打开链上应用的桌面浏览器。网站文件存放在 IPFS，版本登记在 X Layer，每次打开前先核对链上绑定。

**[从 GitHub Releases 下载 →](https://github.com/cybercity001/fab-browser/releases)** · macOS Apple Silicon · Windows x64 · Linux x64 · 测试预发布版

---

## 它是什么

一个标签列，加上页面。标签放在左侧，页面占满其余的高度；也可以把标签放到顶部，按 `⇧⌘S` 切换。没有工具栏，没有推荐内容，访问应用也不需要钱包或账号。在唯一的地址栏里输入应用名称、容器地址或 `fab://` 链接，就能打开。

它基于 [TapeBrowser](https://github.com/trytotapeout/TapeBrowser) `5f1d82c`（GPL-3.0-or-later）改写，界面参考了 [Search](https://github.com/driceroland/Search) 的设计。存储方式是 FAB 的：**IPFS 文件 → Registry 登记 CID 与版本 → 独立 HTTPS 网关**。目前接的是 FAB DeWEB 测试 Registry `0x4Ab6…D506`；X Layer 196 是真实主网。

## 它能做什么

- **一个地址栏。** 输入应用名称、容器地址、电路地址 `#NFT ID` 或 `fab://容器地址/`，打开的是链上登记的最新版本。普通 HTTP/HTTPS 网页在独立会话中打开，地址栏左侧的标记会说明它没有经过链上核验。
- **开始页。** 两款精选应用：五子棋（电路 #3）和德州扑克（电路 #5），点卡片就打开链上登记的最新版本；下面说明打开之前核对了什么。
- **第一次打开有引导。** 五个短页面：这是什么、语言与外观、两种布局、钱包、几个快捷键。每页都可以跳过，之后可以在 设置 › 重新查看引导 再看一次。
- **两种布局。** 侧边栏模式下，标签、书签应用和当前网站的版本、CID、容器都在左列；顶部模式下，标签排成一行。窗口窄于 700 像素时，标签列改为盖在页面上展开。
- **固定区。** 地址栏下方的方块是固定的网站，默认有 OKLink 和 FAB。右键标签页选“固定”加入，右键方块选“取消固定”移除。书签（`⌘D`）与最近访问在 `⇧⌘B` 面板里管理。
- **应用目录。** 从 FAB Registry 的发布事件发现应用，支持搜索、分类、排序和分页。刷新时有进度显示，可以取消，检查点会保存下来。目录快照只是缓存，真正打开应用时仍会重新核对链上绑定。有独立网关的应用可以直接打开，其他应用要先填写网关，并核验网关的实际响应。
- **固定历史版本。** 明确写出 `/v/1/index.html` 的地址读取 Registry 中的版本 1，每个版本使用独立会话。刷新固定的历史版本不会把它升级到最新版；访问容器入口才会解析最新版。
- **网站信息。** 点地址栏左侧的标记，可以看到 CID、版本、发布者、发布文件和被阻止的外部资源，还可以检查最新版本和当前 NFT 持有人。
- **内置钱包。** 窗口顶部角落的钱包按钮：创建或导入钱包，查看 OKB 余额和地址，锁定、备份。私钥用密码加密保存在本机。网站第一次读取地址、每次签名或发交易，都要在 FAB 里确认。也可以改用浏览器扩展。
- **预览本地网站。** `⌘O` 选择构建目录：本地修改后自动刷新，可以打开所在目录，并运行引用检查和静态安全检查。外部资源默认阻止。发布通过已有的 FAB 开发者中心完成。
- **浅色、深色，或跟随系统。** 窗口和其中的页面都跟随这个设置。
- **设置。** 语言（中文 / 英文 / 跟随系统）、外观、RPC 验证与保存、缓存容量与清理，以及已核验的历史版本列表。

## 它不做什么

这些是有意的：

- 不把私钥交给网页，不内置扩展商店。未知的钱包方法一律拒绝，内置钱包只在 X Layer 196 上签名。
- 不向应用暴露 Node、Electron 管理 IPC、文件系统或设备权限，只注入受限的 EIP-1193 / EIP-6963 钱包接口。
- 不自动购买域名，不自动创建网关。
- 不收集遥测数据，没有自动更新器。
- 没有实现矿机奖励或加速、官方 DomainBinding 费用，也不支持原版 `tape://` 链上文件格式。

## 信任，具体来说

| 什么 | 怎么核对 | 局限 |
|---|---|---|
| 应用绑定（CID、版本、容器） | 两个 HTTPS RPC 在同一区块读取，结果必须一致 | 主机名不同不代表运营方相互独立 |
| 文件内容 | SHA-256 对照**网关发布清单**校验；缓存身份包含链、Registry、容器、版本和 CID | **没有独立验证 IPFS DAG**，因此仍需信任网关提供的清单和内容来源 |
| 缓存 | 历史缓存需要你明确选择，并标为"当前链上版本和所有权未核验" | 缓存不保证已下载全站；未缓存的文件仍依赖 IPFS Pin 和网关 |
| 发布权 | 由合约实时检查；电路 NFT 管理网站的发布权 | 浏览器目录本身不授予发布权 |
| 内联脚本与样式 | 只放行已校验 HTML 中内联 `<script>`、`<style>` 原文的 SHA-256，与 FAB 网关的规则相同；内联事件属性和样式属性一律阻止 | 网站仍不能联网，例如德州扑克的联机模式不可用 |
| 静态安全检查 | 报告列出了哪些文件没有扫描 | 不能证明网站安全；单个文件扫描上限 4 MiB，总上限 24 MiB |

当前的 Pin 副本还放在一台开发电脑上，关机后无法保证未缓存的资源可用；AWS 上的独立节点另行处理。两款精选应用使用 `r2-<容器地址>-deweb-test.fabx.tech` 网关。

## 东西存在哪里

| 什么 | 位置 | 谁能读 |
|---|---|---|
| 设置、网站授权、桥接口令 | userData 下的 `fab-settings.json`（权限 0600） | 你 |
| 书签、访问历史 | userData 下的 `fab-library.json` | 你 |
| 目录快照与检查点 | userData 下的 `fab-catalog.json` | 你 |
| 已核验的发布文件 | userData 下的 `content-cache/`，默认上限 512 MiB | 你；设置里可以清空 |
| 内置钱包 | userData 下的 `fab-wallet.json`（权限 0600，scrypt + AES-256-GCM） | 只有你的密码能解开；解锁后私钥只在主进程内存中 |
| 扩展钱包（可选） | 你的钱包扩展；FAB 只经过 `127.0.0.1` 上带口令的桥接页转发请求 | 你批准过的网站，且每次签名都要确认 |

在 macOS 上，userData 是 `~/Library/Application Support/fab-browser/`。

## 开发者

### 构建

需要 Node.js 22 和锁定版本的 pnpm 10：

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm smoke
pnpm start
```

`build` 校验源码并生成 `dist/`，不生成安装包。`src/config.mjs` 管理固定的 FAB 测试 Registry、默认 RPC 和已核验的网关；用户设置保存在 Electron userData 中。`src/catalog-seed.json` 是用两个 RPC 实际扫描得到的发布目录快照，刷新时先核对检查点哈希，再增量读取。测试部署地址和上游来源见 [UPSTREAM.md](UPSTREAM.md)。

### 结构

- `ui/` 是受信任的外壳：`index.html` 定义标签列（或顶部标签栏）、地址栏、开始页、查找栏、管理面板和引导页；`app.js` 负责标签与布局，`management.js` 负责设置、钱包、目录、书签和网站信息，`welcome.js` 负责首次引导。`style.css` 顶部的颜色变量都是浅色、深色成对的，其他样式只引用这些变量。
- `src/desktop-layout.mjs` 计算应用视图的位置：侧边模式下在标签列右侧占满高度，顶部模式或窄窗口下在 44 像素的标签栏之下，查找栏打开时再下移 44 像素。
- 链上权威只在 `src/resolver.mjs` 和 `src/chain-reader.mjs`；钱包相关代码在 `src/local-wallet.mjs`（内置钱包）、`src/bridge-server.mjs`、`src/provider-host.mjs`、`electron/site-preload.cjs` 和 `bridge/`。

### 验收

本地逻辑、文件和 WebSocket 集成测试覆盖撤权竞态、导航取消、目录断点、最大 NFT 编号、缓存并发与损坏、候选网关强制核验，以及固定历史版本。真实 Electron 的 smoke 会依次走完五页引导，截取开始页的浅色和深色截图，然后先验证当前发布版本，再固定历史版本 2，验证五子棋完整对局、从开始页打开德州扑克并确认它以链上核验状态渲染、普通网页隔离、两种布局与三种窗口宽度、本地目录热刷新、隐藏文件阻止、历史缓存、目录和语言切换。每次运行都把带时间戳的 JSON 和截图保存到被 git 忽略的 `artifacts/` 中。

内置钱包在 smoke 中经由真实面板创建、备份、连接网站、签名、锁定、解锁并删除（没有资金）。扩展钱包测试使用**没有资金的模拟扩展**，请求经过真实的 preload → 主进程 → 本机认证 WebSocket 链路转发，但这不等于真实扩展的交易验收。测试没有广播任何链上交易。`--fab-smoke` 使用独立的临时用户目录和仅供测试的原生对话框替身，正常客户端不会启用它。

### 客户端发布

目标平台：macOS Apple Silicon（M 系列）DMG、Windows x64 NSIS、Linux x64 AppImage。GitHub Actions **Build and verify clients** 在三个原生 runner 上构建，安装或解包后启动实际客户端执行 smoke；任何一个平台验证失败，都不会上传该平台的安装包。测试依赖真实的 FAB 测试 Registry、两家公共 RPC 和网关，失败记录保留在 Actions artifacts 中。

三个平台都通过后，发布公开的 GitHub **prerelease**，附带对应的源码 ZIP、客户端安装包、SHA256SUMS 和验收证据。不提供 Intel Mac 客户端。macOS 版本使用 ad-hoc 签名，没有经过公证；Windows 版本没有 Authenticode 签名。原生 CI 的启动验证不代表已经覆盖所有用户设备、真实钱包扩展和系统安全提示。
